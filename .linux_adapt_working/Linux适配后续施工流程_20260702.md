## Phase 1：类型系统修复（P1，改善代码质量）

> **目标**：排查并修复 62 个基线既存类型错误，使 `tsc --noEmit` 完全通过。

### 1.1 类型错误分布摸底

核验时已确认 main 侧 `tsconfig.node.json` 有 63 个错误，其中 1 个是 Phase 0 修复项，剩余 62 个集中在：

| 模块 | 错误数（估计） | 典型原因 |
|------|--------------|---------|
| `openforu/` | ~25 | 隐式 any、未使用变量、类型不匹配 |
| `extensions/` | ~25 | 同上，插件系统的松散类型 |
| `desktop-agent/` | ~8 | router 动态导入 resolve 类型 |
| 其他 | ~4 | 零星 |

### 1.2 修复策略

**原则**：最低风险修复，不改动运行时行为。

| 错误类型 | 修复方式 | 风险 |
|---------|---------|------|
| `TS7006: Parameter implicitly has 'any'` | 补充类型注解或 `: any` | 零风险 |
| `TS6133: declared but never read` | `_prefix` 或删除 | 零风险 |
| `TS2345: Argument of type X not assignable to Y` | `as` 类型断言 | 低风险 |
| `TS2339: Property does not exist` | 扩展接口或 `(obj as any).prop` | 低风险 |

### 1.3 施工步骤

```
1. 运行 npx tsc --noEmit -p tsconfig.node.json > errors.txt
2. 按文件分组，评估每个文件的错误密度
3. 从低密度文件开始（1-2 个错误的文件），逐个击破
4. 高密度文件（10+ 错误）用 `as any` 或补充接口定义批量修复
5. 每修复一批就跑一次 tsc 确认计数下降
6. 最终目标: npx tsc --noEmit -p tsconfig.node.json → 0 errors
```

**工作量**：62 个类型错误，预计 2-4 小时。可分多次提交。

## Phase 2：Go 启动器平台化（P2，完成图纸要求）

> **目标**：改造 `launcher/main.go`，使其能在 Linux 上编译运行。
> **图纸参考**：[linux-adapt-blueprint.md](linux-adapt-blueprint.md) Layer 5.1

### 2.1 当前硬编码问题

| 行/区域 | 问题 | 改造方案 |
|---------|------|---------|
| 二进制名 | `Ackem.exe` 硬编码 | 使用 `runtime.GOOS` 判断，或 `//go:build` 标签 |
| SysProcAttr | `syscall.SysProcAttr{HideWindow: false}` | 仅 Windows 有效，用构建标签分离 |
| AllocConsole | `kernel32.AllocConsole()` | `//go:build windows` 包裹 |
| robocopySync | Windows 专有 | 替换为 `os.CopyFS()`（Go 1.21+）或 `rsync -a` |
| sevenZipPath | `resources/tools/7za.exe` | Linux 查找 `7za` / `7zz` 于 PATH |
| resolveStagingDir | 硬编码 `win-x64` | 使用 `runtime.GOOS`/`GOARCH` 派生 |

### 2.2 推荐文件组织

```
launcher/
├── main.go              # 公共逻辑（平台无关）
├── main_windows.go      # //go:build windows
├── main_linux.go        # //go:build linux
├── go.mod
└── ackem-launcher.mjs
```

### 2.3 改造要点

**`main.go`**（公共逻辑）：
```go
package main

import (
    "os"
    "runtime"
)

func appBinaryName() string {
    if runtime.GOOS == "windows" {
        return "Ackem.exe"
    }
    return "ackem"
}

func platformArch() string {
    return runtime.GOOS + "-" + runtime.GOARCH
}
```

**`main_windows.go`**：
```go
//go:build windows

package main

import "syscall"

func platformSysProcAttr() *syscall.SysProcAttr {
    return &syscall.SysProcAttr{HideWindow: true}
}

func platformAllocConsole() {
    // kernel32.AllocConsole() 调用
}
```

**`main_linux.go`**：
```go
//go:build linux

package main

import "syscall"

func platformSysProcAttr() *syscall.SysProcAttr {
    return nil // Linux 不需要
}

func platformAllocConsole() {
    // Linux 上无需操作
}
```

### 2.4 Robocopy 替换

```go
// 原 robocopySync() → 替换为
import "io/fs"

func copyDirSync(src, dst string) error {
    // Go 1.21+ 内置
    return os.CopyFS(dst, os.DirFS(src))
}
```

### 2.5 7za 查找

```go
func resolve7zaPath() string {
    if runtime.GOOS == "windows" {
        return filepath.Join("resources", "tools", "7za.exe")
    }
    // Linux: 查找系统 PATH
    for _, name := range []string{"7zz", "7za"} {
        if path, err := exec.LookPath(name); err == nil {
            return path
        }
    }
    return "7zz" // fallback
}
```

### 2.6 验证

```bash
# Linux 构建验证
cd launcher && GOOS=linux GOARCH=amd64 go build -o ackem-launcher .

# 交叉编译验证（Windows 上编译 Linux 版，或反之）
GOOS=windows GOARCH=amd64 go build -o AckemLauncher.exe .
```

**工作量**：~200 行 Go 代码，预计 4-6 小时（需要 Go 工具链）。

## Phase 3：构建脚本平台化（P2，完成图纸要求）

> **目标**：改造 `scripts/build-green-release.mjs`，支持在 Linux 上执行完整构建流程。
> **图纸参考**：[linux-adapt-blueprint.md](linux-adapt-blueprint.md) Layer 5.3

### 3.1 改造清单

| 行 | 当前 | 改造 |
|----|------|------|
| 19 | `greenName` 无平台后缀 | 改为动态平台后缀（`ackem-linux-x64` / `ackem-win-x64`） |
| 44 | `win-unpacked` 硬编码 | 使用 `ELECTRON_UNPACKED_DIR` 变量 |
| 66 | `taskkill` Windows 命令 | 平台判断：Linux 用 `pkill` 或 `kill` |
| 80 | `robocopy` Windows 命令 | 平台判断：Linux 用 `rsync -a` 或 `fs.cpSync` |
| 122 | `7zip-bin/win/x64/7za.exe` 路径 | 平台判断：Linux 用 `which 7zz` 或 `which 7za` |
| 177 | `patch-exe-metadata.mjs`（rcedit） | Linux 跳过（rcedit 仅 Windows） |

### 3.2 实现策略

**方案 A（推荐）**：在脚本中加 `if (process.platform === 'linux')` 分支。

```javascript
// build-green-release.mjs 关键改法

import { PLATFORM_ARCH, ELECTRON_UNPACKED_DIR } from '../src/shared/platform.ts'

// Line 19: 动态后缀
const greenName = `Ackem-green-${PLATFORM_ARCH}`

// Line 44: 动态目录
const unpackedDir = path.join('dist', ELECTRON_UNPACKED_DIR)

// Line 66: 进程终止
function killElectron() {
  if (process.platform === 'win32') {
    execSync('taskkill /f /im Ackem.exe 2>nul', { stdio: 'ignore' })
  } else {
    execSync('pkill -f ackem 2>/dev/null || true', { stdio: 'ignore' })
  }
}

// Line 80: 目录同步
function syncDir(src, dst) {
  if (process.platform === 'win32') {
    execSync(`robocopy "${src}" "${dst}" /MIR /NJH /NJS /NDL`, { stdio: 'ignore' })
  } else {
    execSync(`rsync -a --delete "${src}/" "${dst}/"`, { stdio: 'ignore' })
  }
}

// Line 122: 7za 路径
function get7zaPath() {
  if (process.platform === 'win32') {
    return path.join('node_modules', '7zip-bin', 'win', 'x64', '7za.exe')
  }
  return '7zz' // 系统 PATH
}

// Line 177: 跳过 rcedit
function patchExeMetadata(exePath) {
  if (process.platform !== 'win32') {
    console.log('Skipping rcedit (not on Windows)')
    return
  }
  // 原有 Windows 逻辑...
}
```

**方案 B**：拆分为 `build-green-release.mjs`（公共逻辑）+ `build-green-release-win.mjs` + `build-green-release-linux.mjs`。

推荐方案 A（改动最小，便于维护）。

### 3.3 验证

```bash
# Linux 环境
node scripts/build-green-release.mjs
# 确认产出 dist/ackem-linux-x64/ 目录
```

**工作量**：~50 行 JS，预计 1-2 小时。
